Qianfan Tidal CLI

一条命令，查清资源

给训练 Agent 的只读资源入口，查询 cluster-b、cluster-a、cluster-c。

一分钟安装 查看 Agent 模板
qianfan-tidal 示例输出，不代表当前资源 
$ qianfan-tidal all

NAME       QUOTA   USED  AVAILABLE    UTIL
cluster-b      128     96         32   75.00%
cluster-a      158     56        102   35.44%
cluster-c      326    144        182   44.17%

# Agent 需要结构化结果时
$ qianfan-tidal all --json
只读查询 不提交、不删除，也不自动选择集群。
实时快照 每次执行都重新读取当前资源。
Agent 友好 默认表格给人看，JSON 给自动化流程读。

安装 wheel，所有工作区可用

安装包位于团队共享 CFS。uv 会创建独立工具环境并安装依赖，不污染业务项目的 Python 环境。

前置条件 运行环境能访问共享 CFS，并且已经安装 uv。
安装 wheel 为用户级工具 
command -v uv
WHEEL=/srv/research-ops/workspaces/COMMON/qianfan_tidal_metrics-0.1.0-py3-none-any.whl
uv tool install "$WHEEL"
qianfan-tidal --help
qianfan-tidal all
验证成功 command -v qianfan-tidal 能返回命令路径，执行 uv tool list 能看到安装包。
更新 wheel 新包发布后执行 uv tool install --force "$WHEEL" 覆盖安装。

日常只需要这些命令

使用 all 查询全部资源池。需要交给 Agent 解析时，增加 JSON 输出参数。

qianfan-tidal all

查询 cluster-b、cluster-a、cluster-c，输出适合直接阅读的表格。

qianfan-tidal all --json

查询三个集群并输出 JSON。Agent 和脚本优先使用这个形式。

qianfan-tidal cluster-a

只查询一个集群。可替换为 cluster-b 或 cluster-c。

qianfan-tidal --help

查看完整用法和支持的集群短名。

字段怎么读

字段 含义
quota default 队列当前配额卡数。
used default 队列当前已消费卡数。
available max(quota - used, 0)，这是判断能否容纳任务的主口径。
utilization_pct default 队列使用率，仅用于辅助观察。
JSON 结构示例 
[
  {
    "name": "cluster-a",
    "quota": 158.0,
    "used": 56.0,
    "available": 102.0,
    "utilization_pct": 35.44
  }
]

数值仅用于展示结构。资源会随任务启动和结束持续变化。

让 Agent 先查询，再建议

CLI 只返回事实。所需卡数、候选集群优先级和提交权限仍由任务规则决定。

读取任务配置 从 config.yaml 得到节点数和每节点卡数。
查询实时资源 执行 qianfan-tidal all --json 获取新快照。
比较 available 筛出能容纳本次任务的候选集群。
报告建议 给出观察时间、证据和下一步，不伪装成已提交。
可直接放入 AGENTS.md 
## 潮汐资源预检

- 处理 cluster-c、cluster-b、cluster-a 上的任务前，先运行
  `qianfan-tidal all --json 2>/dev/null` 获取实时资源。
- 从实际 config.yaml 计算 required_cards，使用
  `nodes * GPUs_per_node`，不要从池总量猜测。
- 只把 `available >= required_cards` 的集群视为候选。
- 多个集群都满足时，按项目策略优先：
  `cluster-a`，然后 `cluster-b`，最后 `cluster-c`。
- 报告查询时间、required_cards 和三个集群的 available。
- 资源快照会过期，提交前必须再次查询。
- 命令非零退出时只报告查询失败，不回传底层异常堆栈。
- CLI 是只读工具。查询成功不代表任务已提交或已运行。

注意：上面的优先级属于 Agent 规则，不是 CLI 内置的自动选择逻辑。

适合交给 Agent 执行查询、读取 JSON、计算卡数、比较候选并报告证据。
需要单独授权 提交、重提、删除 LTP 任务，或修改任务资源配置。
不要长期缓存 资源是瞬时状态。旧 handoff 和旧日志不能替代提交前查询。

常见问题

工具安装在独立环境。遇到查询错误时，不要把完整异常堆栈复制到 Agent 日志。

提示 command not found

先执行 uv tool list 确认已安装。如果命令仍不可见，执行 uv tool update-shell，然后重新打开 shell。

提示 uv is required

当前环境缺少 uv。请按团队开发环境的统一方式安装或加载 uv，再重新执行 CLI。

提示 resource query failed

查询在 45 秒内未成功，可能是内部网络、指标服务或临时链路问题。稍后重试；需要排查时由环境维护者查看底层连接状态。

同一分钟看到的数字不一样

这是正常现象。quota 和 used 会随任务变化。做调度判断时记录查询时间，并在真正提交前刷新一次。
